## 1. 目的と方針(合意済み)

- 世界観(昼の空・水面・雲海・飛竜)を保った画面遷移にする。「パッと切り替わる」を避け、見ていて楽しい演出にする
- **雲を抜ける遷移は、世界の中の出来事にする**: 自機を雲の高さまで飛ばし、雲の中で入れ替え、雲の上へ出て完了。カメラだけでなく**自機も雲を抜ける**。雲を急に出したり、位置を変えたりしない
- **雲は水なので、レンズに水滴(水の膜)が付く**。丸い水滴でなく、歪みと流れ(前進の反対向き)がある表現。レンズフレア・レンズダスト・スクリーンディストーションも使う
- 読み込み: **スレッドは使わない**。先読み(タイトルの間に素材を少しずつ読む)と「準備ができるまで保つ」待機状態(雲は動き続ける)
- 主役の遷移を絞って作り込む: **タイトル → ゲーム(雲を抜ける)** と **ゲームオーバー(着水)**。余裕があれば、他の軽い演出も凝る
- 参考: グランブルーファンタジーの確定演出の雲を抜ける部分(レイマーチ雲ではないが、抜けた感じが上手い)、エースコンバット 8 の雲を抜ける部分(雲は薄いが、水滴と抜ける表現が良い)

## 5. 原因の仮説(未検証)

1. 白のちらつき
   - カメラの行列(`view_`)・深度の読み取りが、遷移のパスで正しくない(深度テクスチャの状態、解像度、行列がミラーのまま、など)
   - 検証: 最終パスに「デバッグ表示」を足し、深度・透過率・カメラの高さ・雲の厚みを、個別に画面へ出す
2. 影絵
   - 雲の吸収が強すぎて、自機の距離(約 10〜15 ユニット)で透過率がほぼ 0 になる。自機の色が残らず、手前の雲の色だけが乗る
   - 「自機が霞む」には、自機の距離での透過率を 0.5〜0.7 程度に保つ必要がある(今は雲が濃すぎる)
3. 縦線
   - `GameScene.cpp` の `DrawDebugLine`(`showDebugRail_` が true の間)。Release でも描かれる

## 6. 設計の見直し案(ユーザーと合意待ち)

現在の方式(最終パスで、深度とカメラから世界の雲を後づけする)は、次の点で脆い。

- 雲が「遷移のときだけ現れる」。世界に常に存在するものではない
- 深度の読み取り、2 回のコピー、シーンごとの世界座標の違いなど、壊れやすい前提が多い

**案**: 雲の層を、シーンの描画(3D)の一部にする。
- タイトルでも、ゲームでも、世界の高さに固定された雲の層を、通常の描画で(深度テストつきで)描く
- 遷移は、自機とカメラの「演出(上昇)」と、レンズの効果(水の膜・フレア・ダスト)だけにする
- 雲を抜けたあとのゲームの雲海は、同じ層の上面として、連続して見える

## 8. 落とし穴

- **ビルド**: PowerShell で `MSBuild.exe DirectXGame.sln -p:Configuration=Debug -p:Platform=x64 -m -v:m -nologo`(オプションは `-` 形式)。Git Bash から `/p:` を渡すと、パスに変換されて失敗する。MSBuild は `C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe`
- **シェーダー**: 起動時にコンパイルされるので、ビルドが通っても実行しないとエラーが分からない。事前の文法確認は `dxc.exe -T ps_6_0 -E main -HV 2021 -I <shadersフォルダ> <file>`(`C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\dxc.exe`)
- **行の終わり**: 多くの C++ ファイルが CRLF。Python で書き換えるときは、バイナリで読み書きして改行を保つ。heredoc の中に `'` を含む長い Python を渡すと壊れることがある。スクリプトを Write でファイルにしてから実行する
- **見た目の確認**: ブラウザ上の GLSL プレビュー(`scratchpad` の HTML)で作ってから HLSL へ移す。ただし、エンジン側の深度・カメラ・色空間(sRGB)は、プレビューと違う。移したあとに、必ず実機の録画で確認する
- **新しい .cpp/.h**: `Application.vcxproj(.filters)` / `AbsoluteEngine.vcxproj(.filters)` へ追加が必要
- シェーダーの出力は RTV が sRGB なので、リニア値で書く(雲は表示用の値で決めて、最後にリニアへ戻している)
