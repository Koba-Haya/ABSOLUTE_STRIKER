## 0. 課題の要件と方針

**課題(学校の指定)**
- 一番ダメな例: 2D静止画。画面のどこも動いていない
- 補足: 展示会で適当に見て惹きつけられるインパクト。画面の派手な動き。デモプレイを入れるのもよい

**方針(2026-09-29 合意)**
- 実際に敵を倒す/弾を避けるデモではなく、**タイトル用に見せる動き(移動・バンク・ロール・ブースト)をスクリプトで演出**する
- 舞台は**夕焼けの空と水面**。自機が水面すれすれを飛ぶ
- **確実に届く「動き+カメラワーク」を土台にし、雲と水面は段階的に品質を上げる**(下の段階はしご)。全段階で「その時点で提出できる」状態を保つ
- レイマーチ雲は**余力があれば挑戦**。届かなくても作品として成立する計画にする
- **ユーザーが実装内容を理解していることが必須**(面接で説明できること)。§4 の協働ルールに従う

## 2. 現状(コード確認済み) と 要確認

### 確認済みの事実
- `Application/scene/TitleScene.{h,cpp}`: 黒背景+ImGui(`#ifdef USE_IMGUI`)のみ。`Draw` は `BeginRenderScene()` → `EndRenderScene(projInverse)` だけ。`UsesTimeline()` は false。`Initialize` で `Renderer::InitializePostProcess(1280, 720)` を呼んでいる
- **Release は ImGui を含めない設計**。今のタイトル文字は Release では出ない。→ ロゴ・PRESS START は **3Dモデル(2026-09-29決定)**。第1段階は「文字画像を貼った板ポリ(plane)」、第2段階(余力)は「押し出し(厚み付き)3Dテキストの OBJ」。どちらも素材は §3.5 の方法で生成する。3Dなので水面の反射(L2)にも映る。α表現は `DrawEffectModel`(αブレンド)か Material の Dissolve 機能で行う(要確認 6)
- パイプラインは `AbsoluteEngine/graphics/pipeline/UnifiedPipeline.cpp` の `MakeXxxDesc()` で宣言し、`Renderer.cpp`(60〜110行付近)で `Initialize` して保持する型。`PipelineDesc` のフラグ(`usePSMaterial_b0` / `useVSTransform_b0` / `usePSTextureTable_t0` / `usePSCamera_b2` など)でルートシグネチャが決まる
- **`MakeRandomDesc()` が空シェーダーの手本**: `Fullscreen.VS.hlsl` + 自前 PS、`usePSMaterial_b0` に自前パラメータ CB(`Random.PS.hlsl` の `cbuffer RandomParam`)を載せ、頂点バッファなしの全画面描画
- `MakeSkyboxDesc()`: `depthWrite=false`, `depthFunc=LESS_EQUAL`, `cullMode=NONE`。空パスの深度設定はこれを踏襲する
- 描画順(GameScene の例): `skybox_.Draw()` → オブジェクト → エフェクト → パーティクル → GPUパーティクル(`Renderer::DrawGPUParticles(BlendMode::Add)`)
- シェーダー原本は `AbsoluteEngine/resources/shaders/`。`generated/outputs/*/resources/engine/shaders/` にビルドでコピーされる(**generated 側は編集しない**)
- 深度テクスチャの SRV は取得可能(`DepthBasedOutline` が使っている)。ただし L0〜L3 では深度を読まない設計にする(空は最奥に描くだけ)
- `Spline::GetPoint(waypoints, t)` がある(自機・カメラの経路に使える)
- `BaseScene` に `GetMainCamera()` / `SetMainCamera(std::shared_ptr<GameCamera>)` がある。`GameScene` は `renderer->SetCamera(*GetMainCamera())` で描画している
- ノイズ画像: `Application/resources/noise/noise0.png`, `noise1.png`
- GPUパーティクル(`EmitParticle.CS` / `UpdateParticle.CS`)、`ParticleManager`、`RingEffect` あり(水しぶき・スピード線に流用候補)

### 要確認(着手時に最初に調べること)
1. TitleScene 用の `GameCamera` をどう作るか(`GameScene::Initialize` のカメラ生成部分を手本にする)
2. 自機モデルの読み込み方と、`ModelInstance` を PlayerComponent 抜きで単体描画する方法(`PlayerComponent.cpp` の Initialize 付近と `Renderer::DrawModel`)。**本物の PlayerComponent は使わない**(GameScene 分割リファクタと衝突するため)。見た目だけ流用し、動きはタイトル専用スクリプト
3. 板ポリのモデルを `Renderer::DrawModel` / `DrawEffectModel` で出す手順と、テクスチャ・OBJ の置き場所(`Application/resources/` 配下に `title/` を作る想定)。Object3d 系パイプラインは `alphaBlend=false` なので、フェードは `DrawEffectModel`(αブレンド)か Dissolve で行えるか確認する
4. 新規ファイルを vcxproj と `.filters` に追加するルール → **調査済み(2026-09-30)**: ルートの `DirectXGame.vcxproj` は旧パスの残骸で sln から未使用。実プロジェクトは `Application/Application.vcxproj`(アプリ側)と `AbsoluteEngine/AbsoluteEngine.vcxproj`(エンジン側)。HLSL は vcxproj 未登録で `AbsoluteEngine/resources/shaders/` に置くだけ(xcopy で `resources/engine/shaders/` へ)。画像/OBJ は `Application/resources/` に置くだけ(`resources/app/` へコピー)
5. 水面を「頂点シェーダーで変位」するには VS 側に時間を渡す経路が必要だが、現在の `PipelineDesc` の VS 用 CB は Transform のみ。→ **L0 は頂点変位なしの平面+ピクセルシェーダーで波の法線を計算する方式にする**(低空飛行では輪郭の凹凸はほぼ見えないため)。頂点変位は追加要件が出たときのみ
6. ロゴモデルのフェードイン/点滅の方式 → **解決**: `DrawEffectModel`(unlit・αブレンド・depthWrite=false)で `SetColor` のαを動かす。描画順はロゴを自機より後に描く

## 3. 構成(アーキテクチャ)

```
TitleScene (シーン制御: 入力・遷移・Draw順)
 ├─ TitleDirector   … キーフレームで自機/カメラ/ロゴ演出を動かす(時間→状態)
 ├─ SkyPass         … 全画面パス(最奥)。空・太陽・雲。L3 ではここだけ差し替え
 ├─ WaterSurface    … 水面の平面メッシュ+専用パイプライン。L2 で反射テクスチャを追加
 └─ 自機モデル/パーティクル/ロゴ・PRESS START(3Dモデル)
```

**設計の肝(理由も説明できるようにする)**
- **空は最初から全画面パス**にする。L0 の空(グラデ+太陽)、L1 のノイズ平面雲、L3 のレイマーチ雲がすべて同じパスのシェーダー差し替えで済み、C++ 側の配管をやり直さない
- 空関数(色を返す HLSL 関数)は **`Sky.hlsli` に切り出し、水面の反射(L0)からも呼ぶ**。空と水面の色が自動で一致する
- 水面は最初から専用パイプライン。L2 の平面反射はテクスチャを 1 枚バインドするだけの追加で済む
- 演出は `TitleDirector` に閉じ込める(キーフレーム構造体+補間)。TitleScene に座標をベタ書きしない(先輩フィードバック: クラス肥大化・マジックナンバー回避。`PROJECT_ROADMAP.md` §4 参照)

### 水面の設計(L0-3 の詳細。2026-09-29 提案。方針はユーザーと最終確認)

- **平面はカメラに追従する大きな板**にする(端が見えない)。波の模様は**ワールド座標 XZ でサンプル**するので、板が動いても模様は世界に固定され、自機が飛ぶだけで水面が後ろへ流れる = 低空飛行の速度感になる
- **波の法線 = 大きなうねり + 細かいさざ波**
  - うねり: 方向の異なる sin を 2〜3 本足した解析法線(ゆっくり動く)
  - さざ波: ノイズ/法線マップを 2 層、違う向き・速さでスクロールして合成
- **色**: フレネル(Schlick)で「浅い角度=空を強く反射、真上=深い海色」を混ぜる。深い青緑をベースにし、夕焼けの空色を反射で乗せる
- **太陽の照り返し**: 反射ベクトルと太陽方向から鋭いスペキュラ(べき乗を大きく)を計算し、法線の揺れで太陽への光の道がきらめくようにする。夕焼けで最も見栄えが出る要素
- **遠方**: 距離に応じて法線の強さを弱め(ちらつき対策)、地平線の色へ霞で混ぜる
- **やらない**: 屈折・海底・岸の泡(深度読み取りが必要で効果が薄い)。泡は自機の航跡パーティクルだけ
- **L2 の反射**: 水面 PS が反射テクスチャを画面座標+法線で歪ませてサンプルし、解析反射と混ぜる。空・自機・雲が映る。**ロゴと PRESS START は反射させない**(反射用パスの描画対象に含めないだけで済む。モデルごとの制限機構は不要)
- **理解チェック**: ワールド座標でサンプルすると速度感が出る理由 / フレネルが必要な理由 / 遠方で法線を弱める理由(エイリアシング)


### L1 — 雲と速度感
- L1-1: **ノイズ平面雲**(`Sky.PS` に追加)。空に平面を仮定し、視線との交点でノイズをサンプル(`noise0.png` を fbm 風に 3〜4 オクターブ)。濃度の勾配で陰影、太陽側は明るく縁を光らせる。**濃度関数はユーザーが書く**。理解チェック: 「なぜ勾配で陰影が付くか」「水平線付近が不自然になりやすい理由(記事の欠点)と、どう逃がすか(距離で薄く/霞に溶かす)」
- L1-2: **雲ビルボード**: 既存 `ParticleManager` か板ポリモデルで大きな雲テクスチャを自機の脇・手前に流す。カット④の「雲を突っ切る」= 雲を画面いっぱいに重ねて白フェード
- L1-3: **水しぶき・航跡・スピード線**(GPUパーティクル/RingEffect を流用)
- 完了: カットごとに速度感があり、雲が空と手前で違う速さで流れる(視差)

### L2 — 平面反射
- L2-0: 参考イメージ `title_mock_realistic.png`(2026-09-29 に簡易再現したもの)を目標の見た目とする
- L2-1: 反射用 `RenderTexture` を 1 枚(水面より上のシーンを y 反転カメラで描く: 空・自機のみ。解像度は半分でよい)
- L2-2: 水面 PS で反射テクスチャをサンプル(画面座標+波の法線で歪ませる)。L0 の解析反射との**フレネルによる混合**を残し、失敗時に L0 の見た目へ戻せるようにする
- 理解チェック: 鏡像カメラの作り方(平面に対する行列/カメラ位置の反転)、なぜ画面座標でサンプルするか、水面より下を描かない理由(クリップ)

### L3 — 挑戦枠: レイマーチ雲
- 前提: L0〜L2 が完了し、ユーザーが「やる」と決めたときのみ。着手前に**必要な理解(ボリュームレンダリングの積算式・ジッタ・光の減衰)を口頭で説明してから**書く
- 実装: `Sky.PS` のノイズ平面雲を、雲層(高さの範囲)を視線が通る区間をレイマーチする関数に置換。半解像度で描いて上げるか、ステップ数を 32 程度に制限。地平線より下は計算しない。ライト方向は 3〜4 ステップ
- 保険: 重ければ即 L1 の雲へ戻せるよう、**雲関数を差し替え可能にしておく**(`#define` かパラメータでモード切替)
- 完了: 30fps 以上を維持し、雲に厚み・逆光の縁が出る。維持できなければ採用しない

- シェーダーは HLSL の既存流儀(`float32_t` 系の型、`Fullscreen.hlsli` のようにヘッダー分離)に合わせる。**原本は `AbsoluteEngine/resources/shaders/`** に置く
- 新規 C++ ファイルは `Application.vcxproj` / `AbsoluteEngine.vcxproj` と各 `.filters` に追加する(ルートの `DirectXGame.vcxproj` は使われていない)
- 未実装の空関数や「後で」コメントを残さない(先輩フィードバック観点)。段階ごとに使っていないコードは消す
- 提出物(要素別コンテスト共通): **プログラム説明資料を exe とセットで提出**。§4 の `TITLE_SCENE_NOTES.md` の内容がそのまま説明資料の下書きになる
- 締切 10/7(水)。**10/6 夜に凍結**: Release ビルド確認、動画撮影、提出物確認。10/7 は予備日
- カメラは後ろを向かない仕様(`camera_no_lookback`)はゲーム側の制約。タイトルの演出カメラには関係ない
